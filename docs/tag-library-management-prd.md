# PRD：标签库管理模块

## 1. 文档信息

- 产品：企微智能销售平台
- 模块：用户运营 / 标签库管理
- 版本：V1.0
- 评审对象：产品、前端、后端、算法/AI、测试、实施
- 原型范围：当前一期原型中的标签库管理、AI智能生成标签、AI生成标签库记录、AI自动打标配置、AI打标记录

## 2. 背景与目标

### 2.1 背景

企微智能销售平台需要通过用户标签支撑客户筛选、会话托管、策略洞察、用户群发、销售跟进和后续自动化运营。早期标签如果完全由人工维护，会存在以下问题：

1. 标签体系依赖运营经验，难以及时反映真实客户沟通中的新问题、新需求和新风险。
2. 标签命名、标签组归类和打标规则容易不统一，影响后续 AI 自动打标和人群筛选准确性。
3. SaaS 化后，不同企业对用户数据、业务服务和标签口径理解不同，如果每个客户都靠定制开发维护标签规则，交付成本过高。

因此，本模块需要支持 AI 基于企业知识、智能体提示词、用户沟通数据生成标签库提案，并由人工审核、修改后生效。同时，已生效标签库需要支持 AI 自动打标配置和打标记录追溯。

### 2.2 产品目标

1. 建立一套可被运营、销售、班主任和 AI 共同使用的统一标签库。
2. 支持 AI 生成标签内容和 AI 打标规则，降低人工从 0 到 1 建标签体系的成本。
3. 支持人工审核、修改、通过、驳回，保证标签入库质量。
4. 支持 AI 自动打标任务配置，让系统按指定角色、触发条件和数据来源自动给用户打标签。
5. 支持打标结果追溯，明确 AI 给谁打了什么标签、执行了什么操作、依据是什么。
6. 为后续 SaaS 化预留数据字典、变量字段和客户自定义数据范围能力。

## 3. 核心定义

### 3.1 标签组

标签组是标签的一级分类，由人工控制，示例包括：

- 孩子问题画像
- 家庭关系画像
- 家长认知阶段
- 购买意向
- 产品兴趣
- 跟进策略
- 风险预警
- 运营人群

标签组用于控制展示分类、适用部门角色和是否允许 AI 自动打标。原则上标签组数量要稳定，不建议频繁由 AI 自动新增。

### 3.2 标签

标签是具体可写入客户身上的标准化用户特征，例如“厌学”“价格敏感”“高意向”。标签归属于一个标签组。

标签支持来源标识：

- AI 生成：由 AI 标签生成任务产出，经人工审核后入库。
- 人工创建：由运营或管理员手动新增。

来源标识在界面上用小图标弱提示，不使用大段文字打扰操作。

### 3.3 AI 打标规则

AI 打标规则定义某个标签应该在什么情况下写入用户身上。规则放在标签维度，不放在标签组维度。

每个标签应至少包含：

- 标签适用场景
- 命中条件
- 排除条件
- 可引用的数据依据
- 风险边界

如果人工修改过 AI 生成的规则，人工规则优先级高于 AI 原始规则。

### 3.4 正式标签库

正式标签库是已经审核通过、可在全平台使用的标签体系。会话中心、用户群发、策略洞察、客户资料侧边栏等模块均读取正式标签库。

### 3.5 AI 生成标签库记录

AI 生成标签库记录是 AI 每次生成标签候选结果的任务记录。记录中的变更需要人工审核后才能写入正式标签库。

## 4. 用户角色

| 角色 | 使用目标 | 关键操作 |
| --- | --- | --- |
| 运营管理员 | 维护标签体系，审核 AI 生成结果 | 新增标签组、编辑标签、审核生成记录、配置 AI 自动打标 |
| 销售主管 | 关注标签是否能服务销售筛选和跟进 | 查看标签、查看打标记录、反馈规则问题 |
| 班主任主管 | 关注标签是否能服务课后跟进和风险识别 | 查看标签、查看打标记录、反馈规则问题 |
| AI/算法配置人员 | 配置 AI 标签生成和自动打标逻辑 | 配置输入数据、提示词、变量字段、执行规则 |
| 实施/交付人员 | SaaS 客户初始化标签体系 | 配置客户知识库、导入对话样本、协助客户审核 |

## 5. 信息架构

标签库管理页面顶部提供 5 个入口：

1. 新增标签组：人工创建标签组。
2. AI智能生成标签：打开 AI 标签库生成管理智能体配置。
3. AI生成标签库记录：查看每次 AI 生成标签候选结果和审核状态。
4. AI自动打标配置：配置自动给用户打标签的任务规则。
5. AI打标记录：查看 AI 自动打标执行记录和明细。

页面主体展示正式标签库：

- 标签组列表
- 每个标签组下的标签列表
- 标签组适用部门角色
- 标签组是否允许 AI 自动打标
- 标签 AI 生成逻辑说明
- 标签 AI 打标规则查看与编辑

## 6. 功能需求

### 6.1 正式标签库管理

#### 6.1.1 标签组列表

页面以标签组卡片列表展示，每个标签组展示：

- 标签组名称
- 标签数量
- AI 生成逻辑说明入口
- 适用部门角色
- 是否允许 AI 自动打标
- 上移、下移、编辑、删除操作
- 标签列表
- 添加标签入口

#### 6.1.2 新增/编辑标签组

字段要求：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 标签组名称 | 输入框 | 是 | 标签组一级分类名称 |
| 适用部门角色 | 多选 | 是 | 市场、销售、班主任等 |
| 允许 AI 自动给客户打标签 | 开关 | 否 | 控制该标签组下标签是否允许 AI 自动写入 |
| 状态 | 单选 | 是 | 启用、停用 |
| 初始标签 | 标签输入 | 否 | 支持输入后回车生成标签 |

业务规则：

1. 标签组由人工创建、编辑和排序。
2. 关闭“允许 AI 自动打标”后，AI 不允许直接写入该组下标签，只能在记录中输出建议或原因。
3. 停用标签组后，该标签组不再进入新增筛选和自动打标范围，但历史用户标签需要保留可追溯。

#### 6.1.3 标签管理

每个标签组支持：

- 人工新增标签
- 删除标签
- 点击标签查看 AI 打标规则
- 编辑标签 AI 打标规则
- 展示标签来源小图标：AI 生成、人工创建
- 展示规则是否被人工修改的小图标

业务规则：

1. 标签名称在同一标签组内不可重复。
2. 标签被删除前，需要判断是否已有用户使用该标签。
3. 已被用户使用的标签建议采用“停用/建议删除”机制，不建议物理删除。
4. 标签规则一旦被人工修改，自动打标时使用人工修改后的规则。

### 6.2 AI智能生成标签

入口：标签库管理页面顶部“AI智能生成标签”。

打开方式：侧边栏。

目标：配置 AI 标签库生成管理智能体，让 AI 基于业务资料和真实用户沟通数据生成标签候选结果。

#### 6.2.1 输入数据范围

本期只保留 3 类输入数据：

| 数据来源 | 是否支持配置 | 配置内容 |
| --- | --- | --- |
| 企业知识库 | 是 | 选择现有知识库里的文件 |
| 智能体提示词 | 是 | 选择现有智能体，选择后代表引用该智能体的逻辑提示词 |
| 用户沟通数据 | 是 | 配置样本人群条件，并支持上传导入对话数据文件 |

用户沟通数据配置要求：

1. 支持配置“最近 X 个月加的好友”。
2. 支持配置“用户发出的对话条数超过 X 条”。
3. 系统筛选满足条件的用户，并给 AI 提供这些用户与 AI 的完整对话内容。
4. 支持上传企业提供的代表性用户对话数据文件。
5. 上传文件作为补充样本，不替代系统筛选出的对话数据。

#### 6.2.2 生成标签目标

支持多选：

- 生成标签组
- 生成标签内容
- 生成 AI 打标规则

产品原则：

1. 本期默认建议以“生成标签内容”和“生成 AI 打标规则”为主。
2. “生成标签组”可作为候选建议输出，但正式标签组仍建议由人工确认后创建，避免 AI 频繁改动一级分类。
3. 如果目标只选择“生成 AI 打标规则”，AI 只能针对已有标签补充或优化规则。

#### 6.2.3 审核规则

支持单选：

- 需要人工审核
- 不需要人工审核

本期推荐默认值：需要人工审核。

业务规则：

1. 选择“需要人工审核”时，AI 生成结果进入 AI 生成标签库记录，人工通过后写入正式标签库。
2. 选择“不需要人工审核”时，可以直接写入正式标签库，但本期不建议对生产环境开放。

#### 6.2.4 提示词配置

侧边栏内提供任务提示词文本框。提示词需要明确告诉 AI：

- 行业背景
- 数据来源
- 标签生成标准
- 与现有标签、人工标签的关系
- 标签组数量和每组标签数量限制
- 新增、修改、建议删除的判断标准
- AI 打标规则输出要求
- 医疗、隐私、负面定性等禁止项
- 输出格式

建议默认提示词见附录 A。

### 6.3 AI生成标签库记录

入口：标签库管理页面顶部“AI生成标签库记录”。

打开方式：

1. 点击入口后先打开生成记录弹窗。
2. 弹窗展示每次 AI 生成任务记录。
3. 点击某条记录进入详情页或详情视图。

#### 6.3.1 生成记录列表字段

| 字段 | 说明 |
| --- | --- |
| 生成批次 | 每次 AI 生成任务的唯一编号或名称 |
| 生成时间 | AI 任务完成时间 |
| 生成目标 | 标签组、标签内容、打标规则 |
| 变更数量 | 本批次包含的新增、修改、建议删除数量 |
| 审核状态 | 待审核、部分通过、已通过、已驳回 |
| 操作 | 查看详情 |

#### 6.3.2 生成记录详情

详情严格按照列表展示，不使用散乱卡片。

列表字段：

| 字段 | 说明 |
| --- | --- |
| 变更类型 | 新增标签、修改标签规则、建议删除 |
| 变更内容 | 标签名称，例如“学校适应情况”“家长认知阶段” |
| AI 判断原因 | AI 为什么建议新增、修改或删除 |
| AI 打标依据 | AI 给该标签打标时使用的规则依据，支持人工修改 |
| 操作 | 驳回、通过 |

业务规则：

1. 人工可直接修改“AI 打标依据”后再通过。
2. 通过后写入正式标签库。
3. 驳回后不写入正式标签库，但保留记录。
4. 修改标签规则时，人工通过后新规则成为该标签的当前生效规则。
5. 建议删除时，通过后标签进入停用或删除流程，具体由后端按是否已有用户使用判断。

### 6.4 AI自动打标配置

入口：标签库管理页面顶部“AI自动打标配置”。

打开方式：侧边栏。

目标：配置 AI 何时、给哪个角色下的用户、基于哪些数据自动判断并写入标签。

#### 6.4.1 执行配置

字段要求：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 启用自动打标 | 开关 | 启用 | 控制自动打标任务是否运行 |
| 角色选择 | 多选 | 销售、班主任 | 决定给哪个角色下的用户打标签 |
| 执行对象规则 | 规则列表 | 加好友第 3 天、用户消息超过 10 条 | 满足任一条件即执行 |
| 执行时间规则 | 下拉 + 时间 | 满足以上条件自然日后 1 天 00:00 | 支持自然日后 1/2/3 天和具体执行时间 |

执行对象规则包括两类：

1. 加好友第 X 天打一次标签，支持配置多条。
2. 用户发出的会话信息条数超过 X 条打一次标签，支持配置多条。

规则关系：

1. 加好友天数规则之间是或关系。
2. 消息条数规则之间是或关系。
3. 加好友规则和消息条数规则之间也是或关系。
4. 用户满足任一规则，即进入打标任务队列。

#### 6.4.2 标签与数据范围

本期数据来源只保留：

| 数据来源 | 说明 |
| --- | --- |
| 用户沟通数据 | 默认读取要打标签用户的全部对话数据 |
| 客户档案 | 默认读取企业给到的客户档案数据 |

业务规则：

1. 不需要在此处重复配置允许自动打标的标签组。
2. 外部标签组开关打开，即代表该标签组允许 AI 自动打标。
3. AI 自动打标只能使用已生效标签库和当前生效的标签规则。
4. 人工修改过的标签规则优先于 AI 生成规则。

#### 6.4.3 自动打标逻辑说明

需要提供文本框，让运营或实施人员写明自动打标逻辑。

文本框应支持后续扩展变量字段配置。本期原型可先展示逻辑说明，后续 SaaS 化时接入数据字典和变量选择。

默认逻辑要求：

1. 仅允许对开启“允许 AI 自动打标”的标签组执行自动打标。
2. 每个标签必须依据该标签当前生效的 AI 打标规则判断。
3. 判断依据必须来自用户沟通数据或客户档案，不得凭空推断。
4. 用户只在单条消息中偶然提及，不应直接打标，除非与历史沟通或客户档案相互印证。
5. 新增标签、删除标签、修改标签都需要输出判断原因。
6. 涉及风险、医疗边界、隐私、负面定性时，需输出风险提醒，不做诊断结论。

### 6.5 AI打标记录

入口：标签库管理页面顶部“AI打标记录”。

目标：追溯 AI 自动打标执行结果。

#### 6.5.1 记录列表

列表不展示审核相关内容。

建议字段：

| 字段 | 说明 |
| --- | --- |
| 执行批次 | 自动打标任务批次 |
| 执行时间 | 实际执行时间 |
| 执行角色 | 销售、班主任 |
| 触发规则 | 加好友第 X 天、消息超过 X 条 |
| 覆盖用户数 | 本次参与判断的用户数量 |
| 标签变更数 | 新增、删除、修改总数 |
| 操作 | 查看详情 |

#### 6.5.2 打标详情

详情需要列出 AI 打标签的数据：

| 字段 | 说明 |
| --- | --- |
| 用户 | 被打标用户 |
| 角色 | 用户归属角色 |
| 操作 | 新增、删除、修改 |
| 标签组 | 标签所属分组 |
| 标签 | 标签名称 |
| 原标签状态 | 执行前状态 |
| 新标签状态 | 执行后状态 |
| 原因 | AI 执行该操作的原因 |
| 依据数据 | 关键对话片段或客户档案字段摘要 |
| 置信度 | AI 判断置信度 |
| 操作 | 查看用户 |

业务规则：

1. 支持点击“查看用户”跳转到对应用户的客户侧边栏标签页。
2. 打标记录不可删除，保证审计可追溯。
3. 如果后续标签库规则调整，历史打标记录仍保留当时使用的规则版本。

## 7. 标签变更与历史用户标签处理

### 7.1 问题

如果第一批 AI 生成标签库已经用于给用户打标，后续 AI 又对标签库做了新增、删除或规则调整，需要明确历史用户标签如何处理。

### 7.2 推荐方案

标签库需要引入版本与生效规则概念。

1. 每个标签保留唯一 tag_id，标签名称可修改但 tag_id 不变。
2. 每个标签规则保留 rule_version。
3. 用户身上的标签记录需要保存 tag_id、标签名称快照、rule_version、来源、写入时间、写入原因。
4. 标签规则调整后，不立即覆盖所有历史用户标签。
5. 下一次自动打标任务执行时，系统按新规则重新判断用户标签，产生新增、删除、保持不变或修改记录。
6. 对建议删除的标签，如果已有用户使用，优先停用，不建议直接物理删除。

### 7.3 状态处理

| 标签库变化 | 历史用户标签处理 |
| --- | --- |
| 新增标签 | 新标签进入后续自动打标范围，不影响历史标签 |
| 修改标签名称 | 用户侧展示新名称，但历史记录保留旧名称快照 |
| 修改打标规则 | 后续打标使用新规则，历史标签保留原规则版本 |
| 建议删除标签 | 已使用标签进入停用状态，后续不再新增，历史可追溯 |
| 标签组关闭 AI 自动打标 | 后续不再由 AI 写入该组标签，历史标签保留 |

## 8. SaaS 化与变量配置建议

### 8.1 当前一期边界

当前原型先把数据来源表达清楚，不要求完整实现客户自定义数据字典。

一期可支持：

- 数据来源勾选
- 数据来源下的基础配置
- 逻辑说明文本框
- 后续变量选择入口的设计预留

### 8.2 后续 SaaS 化建议

后续应建设“数据字典 / 变量字段”能力，让不同企业可以配置：

1. 数据来源类型：用户沟通数据、客户档案、订单数据、课程行为、测评数据、企微关系等。
2. 每类数据来源下有哪些字段可以给 AI 使用。
3. 字段变量名，例如 `{{conversation.recent_messages}}`、`{{customer.profile}}`。
4. 字段解释、数据口径、权限范围、更新时间。
5. 哪些变量允许用于标签生成，哪些变量允许用于自动打标。

推荐交互：

1. 在“数据来源”处勾选数据来源类型。
2. 点击配置后，在该数据来源下勾选具体变量字段。
3. 提示词只描述业务逻辑，例如“根据用户沟通数据分析用户主要痛点”。
4. 系统实际给 AI 的上下文由已勾选变量字段决定。

这样比让客户手工在提示词里插入大量变量更稳定，也更适合 SaaS 标准化交付。

## 11. 验收标准

### 11.1 标签库管理

1. 用户可以新增、编辑、删除或停用标签组。
2. 用户可以在标签组下新增、删除标签。
3. 用户可以查看和编辑每个标签的 AI 打标规则。
4. 用户可以设置标签组是否允许 AI 自动打标。
5. 标签来源和规则修改状态有清晰但不打扰的小图标提示。

### 11.2 AI智能生成标签

1. 用户可以打开 AI 标签生成管理智能体侧边栏。
2. 用户可以选择企业知识库、智能体提示词、用户沟通数据。
3. 企业知识库支持选择现有知识库文件。
4. 智能体提示词支持选择现有智能体。
5. 用户沟通数据支持配置样本人群条件和上传对话数据文件。
6. 用户可以选择生成目标和审核规则。
7. 用户可以编辑标签生成提示词。

### 11.3 AI生成标签库记录

1. 用户可以查看 AI 生成任务列表。
2. 用户可以进入某条生成记录详情。
3. 详情按列表展示新增标签、修改标签规则、建议删除。
4. 用户可以编辑 AI 打标依据。
5. 用户可以对每条变更执行通过或驳回。
6. 通过后结果写入正式标签库。

### 11.4 AI自动打标配置

1. 用户可以配置启用状态、角色范围、执行对象规则和执行时间规则。
2. 执行对象规则支持多条加好友天数条件。
3. 执行对象规则支持多条用户消息条数条件。
4. 任一条件满足即可触发自动打标。
5. 数据来源只展示用户沟通数据和客户档案。
6. 用户可以编辑自动打标逻辑说明。

### 11.5 AI打标记录

1. 用户可以查看 AI 自动打标记录。
2. 记录不展示审核相关内容。
3. 详情展示用户、角色、操作、标签、原因、依据数据和置信度。
4. 支持跳转到对应用户的客户侧边栏标签页。

## 12. 暂不实现范围

4. 真实企微消息、订单、课程、测评等数据接口。

## 附录 A：AI标签库生成默认提示词

```text
你是一位资深青少年心理教育行业客户洞察专家，同时也是企业用户标签体系设计专家。你的任务是基于输入的企业知识库、智能体提示词和真实用户沟通数据，生成一套可被运营团队审核、维护、入库和用于 AI 自动打标的标签库候选结果。

一、业务背景

平台服务对象主要是购买体验课或正在了解心理教育服务的家长。家长咨询的核心问题通常围绕孩子学习动力、厌学休学、亲子关系、手机使用、情绪状态、社交适应、课程选择、购买顾虑和服务跟进。

标签库不是用来做医学诊断，也不是用来给用户贴负面评价，而是用于帮助销售、班主任和运营更准确地理解用户状态、筛选用户、生成销售建议和触发自动化服务。

二、你可以使用的数据

1. 企业知识库：包括公司产品服务、课程类型、价格区间、适用人群、服务边界、行业知识和运营资料。
2. 智能体提示词：包括会话智能体和策略智能体当前使用的业务逻辑、沟通目标、服务流程和话术边界。
3. 用户沟通数据：包括筛选出的真实用户与 AI 或员工的完整对话内容，也可能包括企业上传的代表性用户对话数据文件。
4. 现有正式标签库：包括已经生效的标签组、标签名称、标签规则、标签来源和人工修改记录。

三、生成目标

请根据配置的生成目标输出以下内容：

1. 生成标签组：只在现有标签组明显不足时提出建议，不要频繁新增一级分类。
2. 生成标签内容：发现有业务价值、可复用、可被人工理解的标签。
3. 生成 AI 打标规则：为每个标签提供清晰、可执行、可审核的打标依据。

四、标签生成原则

1. 每个标签必须表达一个相对稳定、可复用、对业务有价值的用户特征。
2. 标签不能只是单次聊天中的偶然表达，必须有足够样本支撑。原则上至少需要 10 个独立用户出现相似表达或行为。
3. 同一标签组下标签数量建议控制在 6-12 个，最多不超过 15 个。超过时需要优先合并语义相近标签。
4. 标签命名要短、清晰、业务人员能理解，避免生僻词、内部黑话和过度抽象。
5. 标签应尽量使用行为描述、状态描述或业务意图描述。
6. 不要生成重复标签、语义过近标签或只换说法但业务含义相同的标签。

五、与现有标签和人工标签的关系

1. 生成前必须先与现有正式标签库做去重检查。
2. 如果新发现的标签与现有标签语义相似度大于等于 70%，不要新增标签，应输出“修改标签规则”或“优化建议”。
3. 如果现有标签规则不清晰、不完整或与真实对话不匹配，可以建议修改标签规则。
4. 人工创建的标签优先保留，不得直接建议删除；如果确实重复或长期无业务价值，只能输出“建议删除”并说明原因。
5. 人工修改过的打标规则优先级高于 AI 原始规则，不得覆盖人工规则；如需调整，只能提出建议。
6. 对已经被用户使用的标签，不建议直接删除，应建议停用或合并，并说明历史用户标签如何处理。

六、分析步骤

步骤 1：数据扫描
- 读取输入的用户沟通数据。
- 按用户维度聚合对话内容。
- 提取每个用户的核心诉求、孩子问题、家长状态、购买顾虑、产品兴趣和风险信号。
- 标注高频名词、动词、情绪词和业务动作。

步骤 2：聚类分析
- 将相似诉求、相似行为和相似业务状态的用户归为一类。
- 每类至少需要 10 个独立用户支撑，否则不生成新标签。
- 提取每类用户的共同特征、典型表达和业务价值。

步骤 3：现有标签比对
- 将聚类结果与现有标签库逐一比对。
- 如果已有标签可以覆盖，优先建议优化规则，不新增标签。
- 如果现有标签无法覆盖，才生成新增标签。
- 如果发现现有标签长期无命中、语义重复或规则冲突，可以输出建议删除。

步骤 4：规则生成
- 为每个新增或修改的标签生成 AI 打标规则。
- 规则必须写清楚命中条件、排除条件、证据来源和判断边界。
- 规则必须能被 AI 在后续自动打标任务中直接执行。

七、禁止行为

1. 禁止生成明确医疗诊断标签，例如“抑郁症”“ADHD”“焦虑症”等。可替换为行为或状态描述，例如“情绪低落”“注意力分散”“焦虑倾向”。
2. 禁止生成侵犯隐私的标签，例如具体家庭住址、真实姓名、学校名称、联系方式等。
3. 禁止生成负面定性标签，例如“差生”“问题家长”“不配合家长”等。
4. 禁止基于单个极端个案生成标签。
5. 禁止为了补齐标签数量而生成低价值标签。
6. 禁止覆盖人工修改过的标签规则。

八、风险处理

如果对话中出现自杀、自残、伤害他人、严重失控等极端风险表达：

1. 不要将具体极端词作为普通运营标签生成依据。
2. 应单独输出风险预警说明。
3. 只允许生成行为描述或风险提醒类标签。
4. 必须提示需要人工介入或专业人员确认。

九、输出格式

请按列表输出，每一行代表一个候选变更：

1. 变更类型：新增标签 / 修改标签规则 / 建议删除
2. 归属标签组：标签所属标签组；如果是建议新增标签组，标记为“建议新增标签组”
3. 变更内容：标签名称或标签规则名称
4. AI 判断原因：说明为什么需要新增、修改或删除
5. AI 打标依据：写成可被后续自动打标直接使用的完整规则，包括命中条件、排除条件、证据来源和风险边界
6. 样本支撑：说明独立用户数量、典型表达和主要数据来源
7. 与现有标签关系：说明是否重复、相似、合并或替代
8. 建议审核动作：通过 / 修改后通过 / 驳回 / 停用

十、质量要求

1. 输出结果要少而准，优先保证标签质量，不追求数量。
2. 每个标签组建议保留 6-12 个高价值标签。
3. 所有标签和规则必须能解释给一线销售和班主任。
4. 所有 AI 打标规则必须能落到真实数据字段或对话证据上。
5. 所有建议都必须说明原因，不允许只给结论。
```
