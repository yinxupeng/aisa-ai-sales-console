# 企微智能销售原型当前对齐说明

本文档用于后续新开 Codex 任务时快速恢复项目上下文。新任务开始前，先阅读本文档和当前代码，再按用户指定范围修改。不要只根据历史记忆改动。

## 1. 项目定位

本项目是企微智能销售平台的一期产品原型，重点服务已购买 4 节体验课的家长用户，目标是帮助销售和运营把体验课用户转化为正价课用户。

平台不是单纯客服系统，也不是普通聊天机器人，而是围绕企业微信托管、会话记录、角色流程、会话智能体、策略智能体、Skill、工具、知识库、标签库、客户档案和群发运营构建的后台管理系统原型。

当前原型只要求产品功能和交互逻辑成立，不要求真实后端能力。

## 2. 业务对象

- 服务对象：有心理健康问题、学习问题、亲子沟通问题的孩子家庭。
- 沟通对象：主要是家长，不是孩子本人。
- 课程对象：课程主要给家长上，用于帮助家长理解孩子问题、改善亲子沟通、推动后续正价课转化。
- 当前重点用户：购买体验课的家长，尤其是体验课后未报名正价课的用户。

## 3. 总体功能关系

```text
工作台
  -> 运营基础数据概览

会话中心
  -> 查看企微托管后的客户会话、客户资料、课程信息、销售策略和服务计划

企微托管
  -> 通过句子互动能力打通企微主动发消息能力，让 AI 扮演真人销售服务用户

智能体
  -> 角色管理
  -> 智能体管理
  -> Skill 管理
  -> 工具管理
  -> 知识库管理
  -> 拟人化设置

用户运营
  -> 标签库管理
  -> 用户群发
  -> 策略洞察
```

## 4. 角色、智能体、Skill、工具、知识库关系

### 角色管理

角色代表一个岗位或服务角色，例如销售、班主任、市场。角色管理重点配置这个角色按什么流程服务用户。

角色管理里不再配置智能体本身的基础能力，也不再维护模型、工具、Skill 等能力细节。角色管理保留“角色流程管理”，用于配置每个流程阶段绑定哪个智能体。

### 智能体管理

智能体是具体执行某类业务任务的 AI 单元。

当前有两类智能体：

- 会话智能体：参与客户聊天，按照业务 SOP 阶段执行沟通。
- 策略智能体：不直接聊天，但会分析客户和人群，影响销售策略、标签、提示词和定时任务。

会话智能体名称更偏服务流程，例如：

- 19元A类课-课前
- 19元A类课-第一课
- 19元A类课-第二课
- 19元A类课-第三课
- 19元A类课-第四课
- 19元A类课-课后

### Skill 管理

Skill 是可复用的 AI 能力片段，未来供智能体组合调用。Skill 适合沉淀通用、重复、跨场景使用的能力，例如：

- 用户信息总结
- 用户标签判断
- 高意向识别
- 销售建议生成
- 资源检索与推荐

Skill 本身不等于工具。Skill 偏“AI 判断和业务策略能力”，工具偏“确定性的外部动作或数据接口”。

### 工具管理

工具是 AI 可调用的确定性能力，例如查询订单、查询课程、发送通知、获取资源链接等。工具应描述输入、输出、调用条件和使用限制。

### 知识库管理

知识库用于维护 AI 可检索、可引用、可发送给用户的资源。资源可以是文档、文本、图片、视频、音频、链接集合等。

知识库当前采用左侧资源目录、中间资源预览/可读内容、右侧资源信息的结构。新增资源应支持选择资源分类，也就是放在哪个文件夹下。

## 5. 会话中心当前结构

会话中心已经调整为业务部门确认的结构：

```text
顶部筛选
  -> 客户搜索
  -> 托管状态
  -> 标签筛选
  -> 重置 / 搜索

选中用户课程服务阶段
  -> 横向展示该用户当前服务流程阶段
  -> 每个阶段 hover 展示阶段说明、进度、进入时间、下一阶段、预计进入时间

主体区域
  -> 左侧：企微账号列表
  -> 中间：当前企微下客户列表
  -> 右侧：聊天对话框

聊天框右上角
  -> 托管给 AI 开关
  -> 客户资料按钮
```

客户资料按钮打开右侧抽屉。抽屉默认展示“用户信息”Tab，不再包含“聊天内容”Tab。

抽屉当前 Tab：

- 用户信息
- 课程信息
- 销售策略
- 流程阶段

## 6. 会话中心客户列表

客户列表要承担快速筛选和快速判断，不要堆太多长文本。

当前列表字段和信息原则：

- 用户名下方可展示最近沟通时间和最近沟通内容。
- 最近沟通内容默认 1 行，超出省略。
- 已删除企微不要放在企微标签里，应作为系统状态显示在用户名下方，可简化为“删”。
- 客户标签列表中不直接展示全部标签，展示标签数量；鼠标 hover 或气泡展示完整标签。
- 操作项对应抽屉 Tab 或聊天面板，当前为：聊天、资料、课程、策略、计划。
- 阶段进度要靠前展示，避免挤在客户类型后面。
- 列表允许横向滚动，但字段不能挤压、重叠、透明覆盖。

## 7. 用户筛选与标签体系

用户筛选分为两类：

### 用户标签筛选

标签适合表达相对稳定、可被运营理解和复用的人群画像或业务判断，例如：

- 孩子问题画像：厌学、休学、手机成瘾、学习动力弱、情绪失控
- 家庭关系画像：亲子冲突高、父亲参与低、母亲高焦虑
- 家长认知阶段：认为孩子不努力、开始接受心理因素、愿意配合家庭调整
- 购买意向：高意向、观望、价格敏感、需专家背书
- 产品兴趣：父母成长营意向、1V1 咨询意向、家庭陪跑意向
- 跟进策略：适合邀约专家连麦、适合先发案例、适合课后复盘
- 风险预警：孩子高危风险、家长情绪失控、已删除企微
- 运营人群：体验后未报名、适合群发复盘、适合二次邀约

标签选择必须统一使用通用标签选择弹窗组件。所有涉及选择标签的场景，包括会话中心筛选、用户群发筛选、策略任务适用人群、客户资料编辑标签，都应使用同一套标签选择体验。

AI 打的标签需要在标签文案后显示“（AI）”，例如：高意向（AI）。不额外展示“企微同步、标签库、AI打标、人工调整”等来源文字。

### 用户状态筛选

状态适合表达客观、频繁变化、来自系统数据或业务流程的数据，不建议做成标签。

当前用户状态筛选字段：

- 用户状态：纯新用户、仅体验、曾购买398、曾购买4980、其他
- 用户等级：S、A、B、C
- 看课时长：不足10分钟、大于10分钟、大于30分钟、大于60分钟
- 托管状态：已托管、未托管
- 亲子冲突：高、中、低

状态字段可以和标签一起组合筛选，但不要混成一套标签，否则后续维护会失控。

## 8. 标签库管理

标签库在“用户运营”下。

标签库管理支持：

- 添加标签组
- 同步企微标签
- 给每个标签组增加标签
- 按部门角色设置使用范围，例如市场、销售、班主任
- 搜索标签
- 设置每个标签组是否允许 AI 自动写入
- 标签分组支持上下调整顺序

“允许 AI 写入”的含义：该标签组下的标签是否允许 AI 在后续自动给用户打标。重要、敏感或必须人工确认的标签组可以关闭 AI 写入。

标签来源字段暂时不要展示。

## 9. 客户资料抽屉

客户资料抽屉从会话中心聊天框右上角进入。

### 用户信息

上方展示基础信息，下方展示用户标签。

用户标签分为：

- 客户标签：统一标签库管理，包含企微同步标签、平台标签、AI 打标和人工调整。
- 个人标签：销售自己手动输入，只给自己看，不和标签库关联。

客户标签要按标签分类展示和编辑。

### 课程信息

课程信息 Tab 上方展示用户订单，下方展示选中订单对应的课程内容和课节进度。

一个用户可能有多个订单，例如体验课、正价课、其他课程订单。每个订单对应课程名称、金额、状态、课节数量、完成进度等信息。

### 销售策略

销售策略来自策略智能体的个人输出，面向单个用户展示。

内容包括：

- AI 给该用户打了哪些标签
- 个性化用户洞察
- 销售建议
- 个性化提示词摘要
- 个性化定时任务

个性化定时任务每个任务后面要有“确认加入”按钮。人工确认后，逻辑上会自动把该定时任务加入该用户的流程阶段定时任务中。

### 流程阶段

保留当前已有流程阶段内容，用于查看该用户当前服务流程和定时任务计划。

## 10. 策略智能体

策略智能体是不参与聊天、但影响 AI 销售和人工执行策略的智能体类型。

策略智能体配置页复用智能体配置结构，但策略任务配置 Tab 为左右布局：

- 左侧：提示词描述，维护策略智能体的全局角色、输入数据理解、输出原则和共性规则。
- 右侧：策略任务配置结果列表，点击“配置任务”弹窗配置任务。

策略任务当前展示 4 类：

- 用户洞察日报
- 周期标签打标
- 生成策略提示词
- 自动生成跟进任务

策略任务配置字段：

- 任务名称：支持输入或选择预设任务，需考虑未来扩展。
- 触发方式与执行频率：合并为固定时间和周期，例如 1 小时 1 次、每天 1 次、2 天 1 次、1 周 1 次。
- 适用人群：通过统一标签选择弹窗选择标签人群。
- 输入数据范围：保留现有设计，例如会话内容、客户档案、订单、课程行为等。
- 输出结果：个性化销售策略、客户标签、策略提示词、个性化定时任务。
- 输出去向：客户档案、客户标签、系统提示词、策略洞察。
- 任务逻辑描述：用于描述该任务具体判断条件、执行逻辑和输出要求。

关于任务逻辑：

- 左侧提示词写策略智能体的共性原则。
- 每个任务的任务逻辑描述写该任务的具体判断标准和输出规则。

## 11. 策略输出查看位置

策略智能体执行结果分两类：

### 单个用户结果

放在会话中心 -> 用户 -> 客户资料抽屉 -> 销售策略 Tab。

用于销售查看某个用户的：

- AI 标签
- 用户洞察
- 销售建议
- 个性化提示词摘要
- 个性化定时任务

### 群体分析结果

放在用户运营 -> 策略洞察。

策略洞察当前只保留一种洞察类型：用户洞察日报。

日报详情结构：

- 人群整体结论
- 人群分层
- 重点用户清单

去掉：

- AI生成动作结果
- 下一步处理建议
- 多种洞察类型

人群分层里的数字可以点击，点击后弹出对应用户名单；名单中的用户可点击进入该用户会话侧边栏。

重点用户清单操作只保留“查看会话”。

## 12. 用户群发

用户群发在“用户运营”下。

MVP 版本只做人工创建群发任务，不做 AI 自动生成群发，不做审核与风控。

页面包含：

- 群发任务列表
- 创建群发任务侧边栏
- 查看任务
- 编辑任务

创建群发任务规则：

- 选择客户为“全部客户”时，不展示标签选择。
- 选择客户为“筛选客户”时，才展示标签筛选和状态筛选。
- 标签筛选必须用统一标签选择弹窗。
- 状态筛选用于客观状态，例如用户状态、用户等级、看课时长、托管状态、亲子冲突。
- 发送设置选择“立即发送”时，不展示选择时间。
- 发送设置选择“定时发送”时，才展示发送时间。
- 侧边栏里去掉重复模块标题和不必要的“企微关系”字段，让页面紧凑。

## 13. 知识库管理

知识库不是复杂的知识工程后台，当前原型应保持清晰、轻量。

结构：

- 左侧：资源目录和文件，支持文件夹和资源的增删改查。
- 中间：所选资源的预览或可读内容编辑区。
- 右侧：资源信息和状态。

左侧“+”用于在当前文件夹下增加知识类目或资源。新增资源弹窗不需要复杂字段，只保留用户能理解的核心信息：

- 资源分类：选择放在哪个文件夹下。
- 资源名称
- 资源类型：文档、文本、图片、视频、音频、链接集合等。
- 上传文件或输入内容
- 资源说明
- 状态

右侧状态用开关，方便启停。右侧不再展示“资源内容预览”，因为中间区域已经承载预览和编辑。

AI 调用知识库时，重点不是保存原始文件本身，而是让 AI 能知道：

- 这个资源是什么
- 什么时候可以引用
- 是否可以直接发给用户
- 如果是链接集合，如何检索并返回正确链接
- 如果是图片、视频、音频，是否可作为素材发送

## 14. 页面与样式通用规则

- 后台系统默认采用 Ant Design / Ant Design Pro / 飞书后台 / 腾讯云控制台风格。
- 强调信息密度、清晰层级、可扫描性和操作效率。
- 不要做营销型大卡片、夸张视觉或过度装饰。
- 不要随便加粗，标题和重点字段按组件规范处理。
- 不要出现重复页面标题。比如页面顶部已有“标签库管理”，内容区就不要再放一个同名标题卡片。
- 表单控件高度、按钮高度、圆角、间距要统一。
- 列表字段宽度要合理，允许横向滚动，但不能文字挤压、重叠、透明覆盖。
- 操作列如果固定在右侧，整列必须有背景色，不是只有按钮有背景。
- 页面局部样式问题优先用局部 class 修复，避免影响全站 AntD 组件。
- 重要交互改动完成后，需本地构建并用浏览器检查关键页面。


- 原型中哪些未来迭代功能必须保留

## 16. 当前技术与验证

项目当前是前端静态原型：

- React
- Ant Design
- esbuild
- 本地预览：`python3 -m http.server 8010`

常用验证命令：

```bash
node scripts/verify-skill-orchestration.mjs
npm run build
```

实际执行时优先使用项目本地或 Codex runtime 的 Node 环境。构建产物在 `assets/main.js` 和 `assets/main.css`。
