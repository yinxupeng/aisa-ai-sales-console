# AI 销售平台官网首版设计方案

## 1. 官网目标

官网首版目标不是做普通产品介绍页，而是服务后续客户沟通和企业交付。

核心目标：

- 给潜在客户说明平台是什么、解决什么问题。
- 强化“企微 AI 销售托管平台”的专业定位。
- 展示个人版、团队版、企业私有化版三类商业化路径。
- 支撑企业客户预约演示、咨询部署和推进交付。
- 为后续销售材料、演示脚本和客户部署沟通提供统一口径。

官网首版主目标建议设为：**交付背书 + 获客转化**。

## 2. 产品表达定位

官网应避免把产品讲成普通 AI 聊天机器人或智能客服。

推荐定位：

> 面向私域销售团队的企微 AI 销售托管平台。

推荐主张：

> 让 AI 按你的销售流程，持续跟进每一个企微客户。

辅助说明：

> 通过智能体、生命周期流程、Skill/SOP 任务和第三方工具调用，帮助企业把客户跟进流程标准化、自动化、可追踪，并支持本地服务器私有化部署。

## 3. 首版信息架构

官网首版采用单页官网结构，后续可扩展为多页。

页面结构：

1. 顶部导航
   - 产品能力
   - 适用场景
   - 版本方案
   - 私有化部署
   - 预约演示

2. 首屏 Hero
   - 产品名称
   - 一句话价值主张
   - 3 个核心卖点
   - 主 CTA：预约演示
   - 次 CTA：查看版本方案
   - 右侧或背景展示产品界面概览

3. 痛点与价值
   - 销售跟进不稳定
   - 客户阶段不可见
   - 企微客户分散
   - 人工响应不及时
   - AI 执行过程不可追踪
   - 平台对应解决方案

4. 产品核心能力
   - 企微账号托管
   - AI 自动跟进
   - 智能体管理
   - 生命周期销售流程
   - Skill/SOP 任务编排
   - 工具与第三方 API
   - 会话中心人工接管
   - 执行记录与 Prompt 追踪

5. 标准业务闭环
   - 企微账号接入
   - 绑定智能体
   - 客户进入会话
   - 生命周期阶段启动
   - Skill 自动执行
   - 工具调用和任务触达
   - 人工介入或成交转化
   - 执行记录复盘

6. 适用场景
   - 教育培训
   - 咨询服务
   - 本地生活
   - 企业服务
   - 私域转化团队

7. 版本方案
   - 个人版
   - 团队版
   - 企业私有化版

8. 私有化部署能力
   - 本地服务器部署
   - 独立数据库
   - 大模型接入
   - CRM/订单系统打通
   - 权限与审计
   - 专属实施与培训

9. 预约演示
   - 姓名
   - 公司
   - 手机号
   - 需求类型
   - 留言

10. 页脚
   - 产品简介
   - 联系方式
   - 版权信息

## 4. 版本体系

官网参考 WorkBuddy 的“个人版 + 企业版”表达方式，但按 AI 销售平台业务重新设计为三档。

### 4.1 个人版

定位：

> 适合个人销售和小团队负责人快速体验 AI 自动跟进能力。

适合对象：

- 个人销售
- 小团队负责人
- 想先体验 AI 销售能力的用户

核心能力：

- 单个企微账号体验
- 基础 AI 销售对话
- 基础客户跟进
- 基础 Skill 模板
- 简单会话记录
- 标准模型额度

CTA：

- 申请体验

### 4.2 团队版

定位：

> 适合销售团队统一管理企微客户，让 AI 按销售 SOP 自动跟进。

适合对象：

- 5-50 人销售团队
- 教培、咨询、本地生活、企业服务公司
- 希望先用标准版本跑通 AI 销售流程的团队

核心能力：

- 多企微账号托管
- 多智能体配置
- 生命周期销售流程
- Skill/SOP 任务编排
- AI 托管与人工接管
- 执行记录
- 基础第三方接口
- 团队账号与权限
- 运营数据看板

CTA：

- 预约演示

### 4.3 企业私有化版

定位：

> 适合需要本地服务器部署、数据可控和深度业务系统集成的企业客户。

适合对象：

- 中大型企业
- 对数据安全和内网部署有要求的客户
- 需要 CRM、订单系统、企微中台深度集成的客户

核心能力：

- 本地服务器部署
- 独立数据库
- 私有模型或专属模型接入
- CRM / 订单系统 / 企微中台深度集成
- 自定义生命周期
- 自定义 Skill
- 自定义工具和第三方 API
- 权限、审计、日志、备份
- 专属实施和培训
- 验收支持

CTA：

- 联系商务

### 4.4 版本对比维度

版本对比表建议包含：

- 企微账号托管数量
- AI 销售对话
- 生命周期流程
- Skill 配置
- 工具调用
- 第三方 API
- 团队权限
- 执行记录
- 部署方式
- 培训交付

首版不建议写死具体价格，建议使用：

- 个人版：申请体验
- 团队版：预约演示
- 企业私有化版：联系商务

## 5. 内容风格

文案风格：

- 直接说明业务价值。
- 少用空泛 AI 概念。
- 多用企业客户能理解的销售管理语言。
- 强调流程、托管、可控、追踪、交付。

推荐关键词：

- 企微 AI 销售托管
- 私域客户跟进
- 销售 SOP 自动化
- 生命周期销售流程
- Skill 任务编排
- 人工随时接管
- 第三方系统打通
- 执行过程可追踪
- 私有化部署

避免关键词：

- 万能 AI
- 完全替代销售
- 普通聊天机器人
- 纯客服机器人
- 黑盒自动成交

## 6. 视觉方向

推荐视觉方向：

- 企业级 B2B SaaS
- 浅色背景
- 高信息密度但保持清晰
- 以真实产品界面截图或拟真界面为主视觉
- 蓝色、绿色、灰色为主色，表达效率、可信和智能
- 少用抽象科技感光效

页面气质参考：

- Ant Design Pro
- 飞书后台
- 腾讯云控制台
- 企业 SaaS 官网

首屏建议不要做纯插画 Hero，应直接展示：

- 会话中心界面
- 生命周期流程
- 智能体配置
- 执行记录

这样能更快让客户理解产品不是概念，而是可落地系统。

## 7. 技术建议

官网作为独立项目，建议技术栈：

- React
- TypeScript
- Vite
- Tailwind CSS 或 CSS Modules
- 静态单页部署

建议目录：

```text
ai-sales-official-site/
  docs/
    product-context.md
    website-design.md
  src/
    components/
    sections/
    App.tsx
    main.tsx
  package.json
```

首版可以先做纯静态页面，不接后端。

预约演示表单首版可采用：

- 静态展示联系方式
- 或前端收集后提示“已提交”
- 后续再接入真实表单接口

## 8. 首版范围

首版包含：

- 单页官网
- 响应式适配
- 顶部导航
- Hero
- 产品价值
- 核心能力
- 业务闭环
- 适用场景
- 版本方案
- 私有化部署
- 预约演示
- 页脚

首版不包含：

- 登录后台
- 真实支付
- 真实表单提交后端
- 多语言
- 博客
- 文档中心
- 客户案例详情页

这些可以作为后续迭代。

## 9. 验收标准

官网首版验收标准：

- 页面可独立运行。
- 桌面端和移动端布局正常。
- 首屏能清晰表达产品定位。
- 版本体系包含个人版、团队版、企业私有化版。
- 文案不把产品误导为普通聊天机器人。
- 核心能力覆盖当前平台实际功能。
- 私有化部署能力有独立模块。
- CTA 明确，支持预约演示或联系商务。
- 页面无明显文字溢出、遮挡、布局错乱。
- 构建命令可通过。
