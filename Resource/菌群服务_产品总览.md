# PRD：客户自动标签清单与分组（提给平台）

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-08-24 |
| 优先级 | P1 |
| 范围 | 提给平台：建设标签库、提供打标工具，按本清单自动打标；对话后台展示标签，并支持按标签筛选用户发送即时消息 |

---

## 1. 目标与使用场景

自动打标范围见第 3 节。命中即打上对应标签；同一用户可同时有多组、多个标签。

本期平台侧必须支撑两个使用场景：

1. **对话后台看到该用户当前标签**（按分组展示：病症程度 / 行课数据 / 家长意向）。
2. **按标签筛选用户，并对筛出的人发送即时消息**。

---

## 2. 实现方式：标签库 + 打标工具

平台本期需要同时交付两件事：

1. **标签库**：预置第 3 节的标签清单，并把标签打在用户身上，供对话后台展示、按标签筛选、发送即时消息。
2. **打标工具**：供 AI 在对话中调用，把标签库里已有的标签打到该用户上。

### 2.1 标签库（最小可用）

标签库 = 预置标签清单 + 打在用户身上的当前标签。本期能力：

| 能力 | 要求 |
| --- | --- |
| 预置标签 | 按第 3 节清单预置，分三组；打标时使用库内已有标签名 |
| 打在用户上 | 每个用户有当前标签集合；对话页 / 用户详情 / 用户列表都能看到 |
| 分组展示 | 病症程度、行课数据、家长意向分组展示，不要一长串 |
| 按标签筛选 | 支持按一个或多个标签圈人（且 / 或） |
| 即时消息 | 筛出的人群可直接发即时消息 |
| 互斥 | 行课状态（未开课 / 行课中 / 已完课且满勤）同时只留一个；缺课次数（缺课 1 / 2 / 3 节）同时只留一个 |
| 写入 | 提供打标 / 改标 / 删标的接口或工具，写入的就是这套标签库 |

### 2.2 打标工具

- AI 从对话里识别到「躯体化 / 询问商品」等，调用打标工具，把标签库里已有的标签打到该用户上。
- 工具可增删预置标签，不新建标签名。
- 行课数据、回复大于 15、待支付、已约电话、用户问题严重：由系统规则按数据自动写入标签库，随数据变化同步更新（例如缺课从 1 节变为 2 节时改标）。

### 2.3 写入路径

| 标签类型 | 写入标签库的方式 |
| --- | --- |
| 病症程度（除「用户问题严重」）、询问商品、孩子信息完整收集 | 对话中 AI 调打标工具写入 |
| 用户问题严重 | 问题级别 ≥ 3 级时由规则写入，级别变化时同步更新 |
| 行课数据、回复大于 15、待支付、已约电话 | 系统数据规则自动打 / 改 / 删 |

---

## 3. 标签清单与分组

### 3.1 病症程度

来源：与用户的对话。用户提到孩子有下列情况时，打上对应标签。同一用户可同时命中多个病症标签。

| 标签 | 说明 |
| --- | --- |
| 躯体化 | 对话中提到孩子存在躯体化相关情况 |
| 医院问诊 | 对话中提到孩子去医院问诊 |
| 做过心理咨询 | 对话中提到孩子做过心理咨询 |
| 亲子冲突严重 | 对话中提到亲子冲突严重 |
| 暴力倾向 | 对话中提到孩子有暴力倾向 |
| 休学大于半年 | 对话中提到孩子休学超过半年 |
| 用户问题严重 | 用户问题级别达到 3 级及以上（含 3 级）即打标 |

### 3.2 行课数据

**到课 / 满勤定义：**

- 单节课实际在课（观看）时长 **大于 10 分钟**，计为该节 **已到课**。
- 时长 ≤ 10 分钟或未进入课堂，计为该节 **缺课**。
- **满勤**：课程全部应到课节次均满足「时长 > 10 分钟」。
- **已完课且满勤**：课程已结束，且满足满勤。

| 标签 | 说明 |
| --- | --- |
| 已完课且满勤 | 课程已结束，且每节到课时长均 > 10 分钟 |
| 行课中 | 课程进行中 |
| 未开课 | 已有课但尚未开课 |
| 缺课 1 节 | 累计缺课 1 节（单节时长 ≤ 10 分钟或未到课） |
| 缺课 2 节 | 累计缺课 2 节 |
| 缺课 3 节 | 累计缺课 3 节 |
| 课上有评论 | 用户在课堂中发表过评论 |

### 3.3 家长意向

| 标签 | 说明 |
| --- | --- |
| 回复大于 15 | 家长有效回复条数 > 15 |
| 询问商品 | 对话中出现询问商品/价格/报名等意向 |
| 待支付 | 存在待支付订单 |
| 孩子信息完整收集 | 孩子侧关键信息已收集完整（字段清单待与业务对齐） |
| 已约电话 | 已预约电话沟通 |
